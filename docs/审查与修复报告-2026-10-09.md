## 2. 架构、Agent 工作流与数据流

项目从本地广告视频提取可定位的画面和语音证据，交付卖点报告、营销策略或创意方案。核心控制器是单个 LangGraph ReAct Agent；ASR、OCR、洞察和报告是受依赖约束的工具阶段，并非多个自治 Agent 自由协商。

核心调用链：

    CLI agent / Web submit
      → AgentRequest → rule_plan / qwen_plan → validate_plan
      → run_agent → LangGraph 模型选择当前可用工具
      → ingest → timeline → speech / OCR → ledger
      → insights → report / strategy / creative
      → Critic 审核 → 完成或等待人工确认
      → 基于已提取证据的后续问答

| 模块 | 职责与边界 |
| --- | --- |
| agent/core.py、langgraph_backend.py、planner.py | 校验计划、限定工具依赖与预算、执行 ReAct、暂停审核、持久化并恢复会话 |
| ingestion、timeline、speech、ocr、ledger | 视频内容哈希、ffprobe、场景检测/关键帧、隔离推理子进程、统一证据与聚合 |
| insights、strategy、creative、reports | 结构化模型输出、证据引用校验、内部质量审计、HTML/Markdown/JSON 制品 |
| runtime、context、memory | 原子文件写入、文件锁、内容寻址与阶段缓存、上下文压缩/预算、SQLite 对话 |
| web、database | HTTP 上传/聊天/任务/诊断、线程池、鉴权和配额；可选 SQLAlchemy/PostgreSQL 元数据与用户存储 |

视频哈希对应共享 runs/ingest_* 目录；每次 Agent 执行对应 executions/exec_* 和独立交付制品。Web jobs/*.json 跟踪排队与执行状态。PostgreSQL 记录用户、会话、请求、执行、工具调用、上下文版本与反馈；未配置数据库时使用 SQLite 和文件状态。

Prompt 中包含任务契约与证据上下文；输出经 Pydantic schema 与证据引用校验。规划器不能绕过工具白名单、依赖或审核。真实流程验证了工具调用协议，但没有完成系统性对抗 Prompt 注入评测，不能据此宣称已防住所有注入。

### 标准启动与使用

项目 README 中的安装目录已从 AdVista 更正为 AdVista-Agent，并补充开发依赖与验证命令。

    python -m venv .venv
    .venv/bin/python -m pip install -e '.[dev]'
    .venv/bin/advista-agent doctor --config configs/local.yaml
    .venv/bin/advista-agent serve --config configs/local.yaml
    .venv/bin/advista-agent agent /path/to/ad.mp4 --backend langgraph --config configs/local.yaml

## 7. 后续优化顺序

1. 统一视频会话的存储与消息 ID，再补视频请求完整结果重放；先解决反馈和历史一致性。
2. 建立临时 PostgreSQL 集成环境，覆盖会话并发、真实外键、迁移与备份恢复演练。
3. 明确普通工作台的登录/认证方式；将 liveness 与模型/ASR/OCR readiness 分开，并为请求失败保留结构化日志。
4. 固化已验证依赖与推理服务版本，增加 Python 3.11–3.13 CI；随后清理 Ruff 诊断和本机脚本路径。
5. 用长视频、多用户压力及对抗样本验证上下文预算、视觉批次、取消延迟和证据质量，按实测结果优化缓存与模型常驻策略。
