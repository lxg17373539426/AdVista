## 最小规范

问题：缺少产品文本时，旧回答用外观和背景音乐补成产品卖点，掩盖证据缺口。

要求：以相关且可用的 OCR/ASR 支撑产品身份、卖点与广告主张；画面只补充直接可见的形状、颜色、动作。排除占位符、重复编号和无关歌词作为产品依据。事实、广告主张、推断和建议分别标注；无相关文本时营销策略允许 `evidence_refs=[]`，卖点分析省略没有依据的洞察。保留所有审计发现与证据缺口。

决策：组合现有四个技能，不另建 HTML 技能。模型输出 `MarketingAnalysis` 或 `MarketingStrategy`；确定性报告渲染器输出自包含 HTML，转义内容，保留来源、原生折叠、移动端和打印布局、缓存指纹。当前请求目标优先于上传时的原始目标。

失败分类：证据规则被跳过使用强制边界；噪声与有效文本的条件判断使用可观察谓词；错误输出形状使用精确 JSON 契约；审计遗漏使用保留字段要求。卖点措辞与建议内容保留自由度，引用和 schema 无自由度。

脚本：复用现有 SkillForge 检查和确定性报告渲染器，不新增技能脚本。

## 路由与验证范围

SkillForge 默认 discovery 不扫描应用包内的 `ad_vista_agent/skills/`，未注册项目技能的初次全局 triage 误匹配 `html-ppt`。主代理随后将这些技能以 project source、priority 0 注册到 `/tmp/advista-audit/report-history-20261010/skills-index.json`，共 112 个技能；营销技能与 HTML 技能的两项改进查询均为 `USE_EXISTING`。代码 `skills/task_contract.py` 明确已有 `report → selling_points + analysis_report` 与 `strategy → selling_points + marketing_strategy`，因此采用现有应用技能组合。启发式路由结果不作为行为验证。

每个技能的 `evals/` 保存中文正例、近似反例、保留正例和行为断言。真实旧应用失败只有上述噪声素材案例；有效价格规格、压力、审计保留与 HTML 注入等场景是回归检查，不声称每个场景都已有旧模型失败。结构检查与模型行为评估分别记录，静态通过不代表模型必然遵守。

## 全新上下文路由与反驳审查

独立代理先只读四个技能 description，再封存 72 条路由判断：40 条正例中 39 条选择所属技能；20 条近似反例均未选择所属技能；12 条保留正例均选择所属技能。遗漏的是“检查两类报告缓存指纹”，已在 `report-frontend` description 增加精准触发条件，独立代理对该修复做定点复核。这个结果是一次人工语义路由评审，不是产品模型自动触发统计。

正文与代码核对发现组合提示存在两个互斥的“仅输出” schema 指令：`selling-points` 要求 `MarketingAnalysis`，最终营销技能要求 `MarketingStrategy`。已明确前者仅约束洞察阶段，组合最终交付由营销或创意主技能决定 schema；独立复核确认冲突已消除，并增加组合输出回归场景。

审查还发现空洞察与报告 builder 默认拒绝行为之间的差距，主代理已新增明确请求报告时的可选空洞察支持，并保留既有审计 warning/review；默认上传导出行为保持原样。营销模型没有审计字段，共享契约已明确只完整保留实际提供的审计对象，没有输入时不得伪造“通过”状态。

HTML 标题、下载能力与 renderer 缓存哈希的实现差异已转主代理核对，最终代码与真实应用验证结果由本次总报告记录。独立审查证据在 `/tmp/advista-report-skills-ab/fresh-review.json`，不等同于旧/新模型盲 A/B 输出比较。

## 真实 Qwen 行为与盲 A/B 结果

使用应用已部署的 Qwen 服务，对“背景歌词与噪声 OCR”和“有效价格规格旁白混有噪声”两个场景运行旧、新营销技能各三次，共 12 个输出。两版本使用相同输入、相同最终 JSON Schema 和 temperature=0；重复运行验证确定性，不能视为六个独立素材样本。早期试验暴露了可选 `evidence_refs` 被模型省略、合法引用重复和关键帧引用混入问题；最终 schema 要求该字段出现、允许空数组、限定文本 ID，并由程序去重。最终比较使用这份共同 schema，不能把 schema 改动算作技能单独带来的效果。

输出以固定种子打乱 A/B 顺序，独立评审代理只接收输入、断言及匿名输出，不接收版本映射。六组比较均选择新技能。噪声场景中新技能三次均返回空引用并明确无法确认定位、受众与核心主张；旧技能三次均引用噪声和不存在的语音 ID。有效文本场景中新技能仅引用真实产品 OCR/ASR，并把“保温 12 小时”标为广告声称；旧技能混入背景歌词及占位符。记录在 `/tmp/advista-report-skills-ab/qwen-ab-outputs.json`、`blind-pairs.json`、`blind-map.json` 与 `blind-judgment.json`。

评审仍发现新技能把“500 mL”描述为“大容量”而缺少比较基准，部分渠道建议未完整列入假设，收益措辞过于确定。这些属于尚未完全解决的语义风险；不能声称模型输出已经全部可靠。重复合法引用已增加程序去重与回归测试。

真实 14 秒视频在 `/tmp` 副本上复测：营销报告没有引用背景歌词或无关 OCR，列出七项证据缺口；卖点链路独立审查背景语音与十三条 OCR，均未作为产品文字证据使用。删除仅由画面推断的年龄/性别受众洞察，保留两条画面观察/推论，其中含“暗示”的视觉推论降为 `inferred_from_ad`；报告审计状态为 `review`，未自动批准。另用有效价格、规格、产品旁白及注入文本验证分类保留/排除行为。原始用户会话和识别记录未重写。

最终验证：全量测试 373 passed / 14 skipped，隔离 PostgreSQL 专项 34 passed，Ruff、110 个源文件的 mypy 检查及 wheel 构建通过。真实 Chrome 验证历史报告链接恢复，营销 HTML 无脚本、无网络资源请求、包含全部十四条文本来源，支持两项离线下载、390 像素手机布局及打印样式。详细结果见 [会话历史与报告技能修复报告](会话历史与报告技能修复-2026-10-10.md)。
