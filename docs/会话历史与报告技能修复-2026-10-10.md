## 2. 已确认的问题与处理

| 级别 | 问题与证据 | 根因、影响与修复 |

| P1 | 背景歌词与噪声 OCR 被用来支撑产品和画像推论 | 仅核对引用 ID 存在，不能核对语义相关性。新增确定性 OCR 质量过滤与卖点链路的独立文本相关性审查，原文保留；不确定或背景音轨不参与产品洞察。仅以画面推导年龄/性别的受众洞察移入证据缺口，明显视觉推论降级标注。 |
| P1 | 新报告可能沿用旧报告的人工复核批准 | 跟进生成报告后未同步执行状态，也未区分新报告与旧批准。新生成报告重新按自身审计进入待确认或失败状态，清除旧批准；同步当前执行及数据库，避免覆盖同一视频的其他执行记录。 |
| P2 | 重新打开会话后报告按钮消失、证据状态丢失 | 原消息查询没有恢复最新 `answer_versions` 的报告链接等元数据。两种数据库适配器均补齐受限字段恢复；前端只接受当前执行下允许的导出路径，拒绝跨执行或恶意链接。原营销文件实际存在，未生成文件的初始判断已更正。 |
| P2 | 普通会话最多显示首批 100 条，无法查看更早记录 | 列表缺分页。增加后端 `limit/offset`、`has_more/next_offset` 与前端加载按钮，处理失败重试、重复结果和切换竞争；定位当前会话时处理旧筛选条件。 |
| P2 | “直接总结一个卖点解析报告”被判为无需报告；没有洞察时明确报告请求失败 | 将明确报告意图纳入路由，使用本轮目标重新生成洞察。明确报告请求可生成证据缺口报告，保留审计 `review`；默认上传导出仍保留原有空洞察拒绝行为。 |
| P2 | 营销 HTML 缺结构与来源；技能要求相互冲突，引用中出现空括号或重复 | 复用现有四个技能，明确各阶段 schema。营销报告增加目录、摘要卡、假设、缺口、可折叠文本来源、下载与打印；动态 HTML 转义、无脚本/CDN，缓存计入技能与渲染器指纹。清理空括号、引用去重并限定文本 ID。 |
