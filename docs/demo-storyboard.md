# AdVista 90 秒产品演示分镜草案

## 目标

让第一次看到 AdVista 的访客在 90 秒内理解三件事：

1. 上传广告视频后可以得到完整的营销交付物；
2. 结论可以回到视频证据，而不是不可核查的模型文本；
3. 核心分析链路可以在团队自己的 GPU 环境中运行。

## 录制前提

- 使用一条明确允许公开展示的广告视频，或制作一条虚构品牌广告；
- 不使用公司内部视频、真实客户素材、内部 URL、服务器路径和历史会话；
- 先准备一条已经完成的演示任务，避免录屏等待完整推理；
- 录制真实上传和任务提交，再打开同一任务的已完成结果；
- 所有结果中的品牌、路径、用户标识和证据原文在发布前复核。

## 分镜

### 00:00–00:06｜提出问题

**画面**：工作台背景淡入，出现三句短文案：

```text
一条广告视频，表达了什么卖点？
这些结论有证据吗？
下一步还能怎么用？
```

**旁白**：

> 分析一条广告视频，不应该只得到一段无法核查的 AI 总结。

### 00:06–00:18｜上传并选择目标

**画面**：打开工作台，附加演示视频，选择「卖点分析报告」，输入：

```text
分析这条广告的核心卖点、受众线索和转化路径
```

点击发送。

**旁白**：

> 上传广告视频并描述分析目标，AdVista 就会启动一次完整的视频分析任务。

### 00:18–00:31｜展示分析过程

**画面**：快速展示任务阶段：读取视频、分析镜头、识别语音、识别画面文字、整理证据、生成洞察和报告。画面角落标注「演示经过加速」。

**旁白**：

> 系统会自动拆解镜头，提取关键帧、语音和画面文字，再整理成统一的视频证据链。

### 00:31–00:49｜展示营销洞察

**画面**：打开完成的报告，依次展示摘要、核心卖点、叙事结构、受众线索和转化路径。停留在一条状态明确的结论上。

**旁白**：

> AdVista 将视频内容整理成结构化营销洞察，并明确哪些内容来自广告表达，哪些内容仍需要验证。

### 00:49–01:05｜展开证据

**画面**：点击一条卖点，展开证据详情，展示关键帧、时间戳、语音或 OCR 原文和结论状态。

**旁白**：

> 每个重要结论都可以回到对应的时间段、关键帧、语音或画面文字。直接证据、画面观察和营销推断会被分开标记。

**剪辑要求**：这是全片最重要的段落，不要用快速转场；至少保留一次完整的「结论 → 证据 → 关键帧」展开动作。

### 01:05–01:18｜继续生成策略和创意

**画面**：切换到营销策略和创意结果，展示定位、传播主张、Hook、脚本、分镜和 A/B 方案。

**旁白**：

> 基于同一份视频证据，还可以继续生成营销策略、广告脚本、分镜和 A/B 创意方案。

### 01:18–01:25｜视频问答

**画面**：输入问题：

```text
这条广告最需要补充验证的信息是什么？
```

展示回答和引用。

**旁白**：

> 分析完成后，还可以围绕视频继续提问，并保留对原始证据的引用。

### 01:25–01:30｜收束定位

**画面**：AdVista 标识和三行定位：

```text
一条视频，生成完整营销交付物
每个结论，都能回到视频证据
核心分析链路，可在本地运行
```

**旁白**：

> AdVista，把广告视频变成可验证、可执行的营销洞察。

## README 摘要版

完整演示不建议直接转成大型 GIF。建议从完整视频中剪出 8～12 秒低帧率 GIF：

```text
上传视频 → 查看报告摘要 → 展开一条证据 → 查看策略或创意
```

README 中使用：

```markdown
视频演示不在 README 内自动循环播放，使用明确的链接打开：

[观看真实产品演示](docs/assets/advista-real-demo.mp4)
```

## 成片检查

- 是否在前 10 秒说明 AdVista 解决的问题；
- 是否只围绕三个核心亮点；
- 是否展示了至少一次真实的证据展开动作；
- 是否避免展示本地路径、内部地址、用户信息和公司素材；
- 是否标注了加速演示，避免让观众误解真实处理时长；
- 是否把「模型生成」表达为辅助分析，而不是保证正确的自动决策。
